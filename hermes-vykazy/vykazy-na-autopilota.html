Nastavení krok za krokem

Počítej zhruba s jedním odpoledním blokem (můj odhad, ne údaj výrobce). Příkazy jsou pro Mac; rozdíly pro Windows jsou u kroků uvedené.

  1. Rozhodni, kde agent poběží

    Plánované úlohy spouští takzvaný gateway. Podle dokumentace musí běžet, aby se úloha vykonala. Když je počítač ve spánku, zmeškaná úloha se po probuzení spustí jednou (výchozí nastavení cron.catch_up_missed: true).

    • Doporučeno na start: vlastní Mac s Apple Silicon nebo Windows PC. Instalátor Hermes Desktop pro macOS je jen pro Apple Silicon.
    • Ne firemní notebook bez souhlasu IT. Agent umí spouštět příkazy a číst soubory.
    • Později: malý server (VPS) běží nonstop. Pro pokročilé, návod to neřeší.

  2. Stáhni Hermes Desktop a vyber model

    Nejjednodušší cesta, bez terminálu: stáhni instalátor Hermes Desktop ze stránky projektu (Mac: otevři DMG a přetáhni Hermes.app do Aplikací; Windows: otevři soubor .appinstaller). Balíček obsahuje agenta, aplikaci i příkazový řádek. Při prvním spuštění tě provede úvodní nastavení, ve kterém zvolíš poskytovatele a model.

    1. Spusť Hermes Desktop. V úvodním průvodci vyber poskytovatele Kimi / Moonshot nebo Z.AI (GLM) a vlož API klíč.
    2. Kdykoli později: Settings → Providers (API klíče) a Settings → Model → Main model: vyber poskytovatele a model a klikni na Apply. Tenhle hlavní model používají i plánované úlohy.
    3. Napiš do chatu: Reply with OK and today's date. Když odpoví, základ funguje.

  5. Nainstaluj skill „worklog“

    Skill je návod, který si agent načte, když ho potřebuje. Tenhle určuje, jak zapisovat, slučovat a hlavně nevymýšlet hodiny. Ulož ho jako ~/.hermes/skills/productivity/worklog/SKILL.md. description: Capture work notes and draft daily logs and weekly reports

  hermes:
    tags: [timesheet, work-log, reporting]
    category: productivity

# Worklog

Turns voice notes, Plaud meeting summaries, forwarded documents and short text
notes into an evidence-based daily work log and a weekly report / timesheet.
All files live in the WorkLog folder (see AGENTS.md in that folder for the
owner's role, project list, project codes and report format).

## When to Use

- The user sends a message, voice note or file that starts with "log", "worklog",
  "note" or is a shared Plaud summary / transcript.
- The user types `/worklog` with or without text.
- A scheduled job asks for "DAILY CLOSE", "WEEKLY REPORT" or "IMPACT DIGEST".

## Folder layout (inside the WorkLog folder)

- `inbox/` raw inputs, one file per item: `YYYY-MM-DD_HHMM_<source>_<short-title>.md`
- `daily/YYYY-MM-DD.md` daily log
- `weekly/YYYY-Www.md` weekly report (ISO week), optional `.docx` copy
- `impact-log.md` running list of notable contributions
- `templates/weekly-template.md` the employer's report format (if present, follow it exactly)

## Procedure

### A. CAPTURE (any incoming note, voice note or file)

1. Save the raw input to `inbox/` using the naming pattern above. For files, store
   the extracted text, not the original binary. Keep the original wording.
2. Extract work entries. One entry = one activity:
   `start time | duration (h) | project code | category | what was done | with whom | source`
   Categories: Design, Coordination & meetings, Review & QA, Support for others,
   Site, Documentation, Admin, Other.
3. Append the entries to `daily/<today>.md` (create it if missing).
4. Reply in ONE short line: what was logged and anything missing
   (e.g. "Logged 1.5 h P-2301 Review & QA. Missing: who requested it?").

### B. DAILY CLOSE (scheduled, weekdays)

1. Read today's `inbox/` files and `daily/<today>.md`.
2. Merge duplicates (a Plaud meeting and a voice note about the same meeting are
   one entry). Sort by start time.
3. Write the final table to `daily/<today>.md` with a total of hours and a
   "Gaps" list (missing durations, unknown project codes, unexplained time).
4. Add any notable contribution (problem solved, risk caught, rework of someone
   else's output, decision unblocked) to `impact-log.md` with date and source.
5. Reply with: total hours, 3-6 bullet summary, the Gaps list as questions.
   Keep it under 120 words.

### C. WEEKLY REPORT (scheduled, Friday)

1. Read `daily/` files for Monday to today of the current ISO week and the
   week's entries in `impact-log.md`.
2. If `templates/weekly-template.md` exists, follow its structure exactly.
   Otherwise produce:
   - Timesheet table: project code, project name, hours per day, total.
   - Key outcomes (5-8 bullets, outcome first, then evidence).
   - Coordination and meetings (count and total hours).
   - Support and quality assurance for others (see Pitfalls for wording).
   - Next week: open items and risks.
3. Save to `weekly/YYYY-Www.md`. If asked for Word, also create the `.docx`.
4. Reply with a 5-line summary and attach the file using `MEDIA:<absolute path>`.
   This is a DRAFT for the user to review. Never send it to anyone else.

### D. IMPACT DIGEST (scheduled, monthly)

Summarise the last month of `impact-log.md` into 5-10 achievement statements
suitable for a performance review: situation, action, result, evidence.

## Pitfalls

- Never invent hours, people, decisions or project codes. Durations come only
  from recording length, an explicit statement by the user, or a calendar entry.
  If unknown, write `?` and list it under Gaps.
- Every entry must name its source (Plaud recording title and time, voice note
  time, email subject, file name).
- Rework or fixes of other people's work: describe the issue and the fix in
  neutral, factual language. No blame, no adjectives about colleagues, no names
  unless the user explicitly asks. Example: "Corrected grid references in the
  tender drawing set (24 sheets) before issue; prevented a re-issue." NOT
  "Fixed X's careless mistakes again."
- Do not copy full meeting transcripts into reports. Summarise outcomes only.
- Do not include client-confidential details (fees, disputes, personal data)
  in the weekly report unless the user explicitly asks.
- Use the language and spelling set in AGENTS.md (default: British English).

## Verification

- Daily file total equals the sum of the table rows.
- Every row has a source.
- Weekly totals per project equal the sum of the daily files.

  6. Propoj Telegram

    V Hermes Desktop: Messaging → Telegram → Create with QR. Naskenuješ kód v Telegramu, Hermes vytvoří bota, zapíše token a tvoje ID jako jediného povoleného uživatele. Ručně: hermes gateway setup, vyber Telegram a token získej u @BotFather.

    hermes gateway install     # gateway poběží jako služba na pozadí
hermes gateway status

    V chatu s botem pošli /sethome, aby věděl, kam doručovat výsledky. Telegram doporučuji před WhatsAppem: napojení WhatsAppu v Hermes jede přes neoficiální most a dokumentace sama uvádí riziko zablokování účtu a doporučuje samostatné číslo.

  7. Hlasové poznámky

    Hlasové zprávy poslané botovi se automaticky přepíšou na text. Výchozí přepis běží lokálně (faster-whisper, bez API klíče, ne na Intel Macu a Windows ARM64). Nastav angličtinu a slovník jmen a projektů, které přepis jinak komolí:

    hermes config set stt.language en
hermes config set stt.prompt "Revit, BIM, BD, Buildings Department, [jména projektů], [jména kolegů]"

    Návyk: začínej poznámku slovem „Log“. Například: „Log. About an hour and a half on the Kai Tak façade set, correcting grid references before issue.“

  8. Naplánuj denní uzávěrku, týdenní výkaz a měsíční přehled

    Spusť v terminálu (nahraď cestu). Úlohy běží v hongkongském čase díky kroku 3. Naplánované úlohy pak vidíš a spravuješ i v Hermes Desktop.

    hermes cron create "30 18 * * 1-5" "DAILY CLOSE: Use the worklog skill, procedure B, for today's date. Work only inside the WorkLog folder. Reply in English, under 120 words, and end with the Gaps questions." --skill worklog --workdir /Users/TVOJE_JMENO/WorkLog --name "Daily close" --deliver telegram

hermes cron create "0 16 * * 5" "WEEKLY REPORT: Use the worklog skill, procedure C, for the current ISO week. Follow templates/weekly-template.md. Save the Markdown file and a .docx copy in weekly/, then attach the .docx. This is a draft for my review only." --skill worklog --workdir /Users/TVOJE_JMENO/WorkLog --name "Weekly report" --deliver telegram

hermes cron create "0 10 1 * *" "IMPACT DIGEST: Use the worklog skill, procedure D, for the previous calendar month. Save it as weekly/impact-YYYY-MM.md and attach it." --skill worklog --workdir /Users/TVOJE_JMENO/WorkLog --name "Monthly impact" --deliver telegram

    Otestuj hned, nečekej na večer:

    hermes cron list
hermes cron run "Daily close"

    Volitelně, aby šlo na denní souhrn odpovědět opravou a agent věděl, o čem je řeč:

    hermes config set cron.mirror_delivery true

  9. Zabezpeč

    Výchozí nastavení už blokuje nebezpečné příkazy a neznámé uživatele. Na počítači s pracovními daty dokumentace doporučuje přidat ruční schvalování:

    Nikdy nenastavuj GATEWAY_ALLOW_ALL_USERS=true. Token bota nikomu neposílej; při úniku ho zruš příkazem /revoke u @BotFather.

07

Neviditelná práce a opravy za ostatní

Výkaz má ukázat, co se díky tobě nestalo: chyby zachycené před vydáním, nekoordinované podklady, které jsi srovnal. Formuluj věcně, s rozsahem a důsledkem, bez obviňování. Skill to má v pravidlech.

Takhle neFixed the junior team's careless mistakes on the tender set again.
Takhle anoReviewed and corrected grid references on 24 tender drawings before issue; avoided a re-issue to the contractor.
Takhle neHad to redo structural coordination because nobody checked it.
Takhle anoRe-coordinated slab openings with the structural consultant (3 clashes resolved), unblocking the MEP submission.

Soubor impact-log.md se plní sám při denní uzávěrce. Jednou měsíčně z něj agent udělá 5 až 10 vět ve tvaru situace, akce, výsledek, doklad. To je podklad k hodnocení, kde se jinak vzpomíná po paměti.

08

Stupeň 3: firemní systémy (jen se souhlasem IT)

  • Pracovní e-mail. Hermes má vestavěný skill Himalaya pro práci se schránkou přes IMAP/SMTP. Firemní Microsoft 365 často IMAP nebo hesla aplikací vypíná; rozhoduje IT.
  • Přepisy z Microsoft Teams. Hermes má pipeline pro přepisy schůzek z Teams přes Microsoft Graph. Dokumentace uvádí, že k nastavení jsou potřeba práva správce tenantu. Bez IT nejde.
  • Bez napojení: přepis schůzky z Teams si můžeš stáhnout ručně a poslat botovi jako soubor. Agent čte .docx, .pdf, .txt i .md.

Přeposílání firemní pošty do soukromé schránky nebo k externímu AI poskytovateli bývá v rozporu s interními pravidly. Nedělej to bez písemného souhlasu.
